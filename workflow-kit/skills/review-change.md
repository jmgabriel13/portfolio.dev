# Skill: Review Change

Use this before considering work complete.

## Review Checklist

- Does the change match the original goal?
- Are domain rules kept out of delivery/UI code?
- Are expected failures handled without exceptions as control flow?
- Are important branches covered by tests or manual validation?
- Are names clear and intention-revealing?
- Are docs updated only where useful?

## Output

Findings first, then test gaps, then a brief summary.
